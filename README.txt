1) Перевипусти токен бота через @BotFather (старий токен був опублікований у файлі).
2) Встанови Python 3.10+.
3) Відкрий папку проєкту в терміналі та виконай:
   pip install -r requirements.txt
4) Скопіюй .env.example в .env та встав НОВИЙ токен у BOT_TOKEN.
   Для прав адміністратора вкажи свій Telegram ID у ADMIN_IDS. Його можна дізнатися
   командою /myid після запуску бота. Для кількох адміністраторів розділи ID комами.
5) Запусти:
   python Svitlo.py
   На Railway команда запуску: python Svitlo.py
6) У Telegram відкрий бота та виконай /start, обери чергу.
7) /test — тестове повідомлення, /status — стан бота та останньої перевірки, /stop — відписатися від моніторингу.
   Окремі кнопки «Увімкнути сповіщення» та «Вимкнути сповіщення» керують автоматичними сповіщеннями;
   також доступні команди /notifications on та /notifications off.
   Адміністратор може використати /users для списку користувачів, /ban <user_id> [причина]
   для блокування та /unban <user_id> для розблокування. На Railway додай ADMIN_IDS у Variables.
8) Стан користувачів, черги та банів зберігається у bot_state.json поруч зі скриптом.
   Щоб зберегти його після redeploy на Railway, створи Volume з mount path /data
   і додай у Variables: BOT_STATE_FILE=/data/bot_state.json. Не додавай bot_state.json у GitHub.

Графік завантажується через API be-svitlo.oe.if.ua. Коли API публікує графік на наступний день,
бот надсилає підписаним на чергу сповіщення з датою та графіком. Якщо API змінить формат відповіді або буде
недоступне, помилка з'явиться в логах, а бот повторить перевірку під час наступного циклу.
Якщо API повертає порожній список відключень для черги, бот покаже, що за графіком світло
має бути весь день.
